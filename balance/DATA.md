# Data

Balance uses **public reference data** plus a **clearly labelled synthetic dataset**. No real people, societies, card numbers or transactions are used anywhere.

## Sources

| Dataset | Source | Date / version | Units | Reuse terms | Used for |
|---|---|---|---|---|---|
| Merchant Category Codes (MCC) and labels | ISO 18245 / card-network MCC list, as exposed by Stripe Issuing's `merchant_data.category` enum | stripe-node v23 (API `2026-09-30`) | 4-digit code | Public taxonomy | Policy table (`src/lib/mcc.ts`), synthetic generator, rules R1/R2/R10 |
| Societies, members, events, purchases, top-ups | **Synthetic**, generated by `src/lib/seed.ts` with a fixed seed (`20261010`) | Academic year 2025-09-01 → 2026-09-30, plus a few current-term (Sept/Oct 2026) events | EUR, integer cents; times in Europe/Dublin | Ours (fictional) | Everything you see in the app; evaluation set |

## Synthetic dataset

* **5 fictional societies:** Drama, Robotics, Law, Hillwalking, E-Sports, each with 3–4 committee members. Names are invented; emails use the reserved-style domain `ucdconnect.example`.
* **106 events** built from per-society templates (e.g. Drama: *Freshers' Showcase*, *Winter Play*, *Cast Party*; Hillwalking: *Wicklow Day Hike*, *Snowdonia Trip*), weighted to term time (15 Sept–5 Dec, 20 Jan–17 Apr).
* **~443 purchases.** Amounts are log-normal around a per-(society, merchant) median with σ = 0.35, clustered in the 10 days before each event. Restaurant captures sometimes include a ~10% tip, so the captured amount differs from the hold.
* **Merchant descriptors** use real chain names (Domino's, Tesco, Ryanair) only as plausible card-statement text. No real transactions are implied.
* **Funding:** UCD Societies Council grants (Sept, Jan) and sponsor top-ups sized from each society's planned spend. Drama's 2025/26 year ends with unspent money returned to the Societies Office, leaving €180 carried over for the demo.

### Labelled anomalies (~12%)

| Type | Count | How it's generated |
|---|---|---|
| `blocked_mcc` | 7 | Gambling, wire transfer, ATM, tobacco |
| `personal_purchase` | 9 | Plausible-looking personal buys on the wrong event (electronics on a social, Zara on a careers evening, Netflix on a workshop) |
| `split_purchase` | 10 | Two purchases at 85–98% of the per-purchase cap within 1–3 hours |
| `duplicate` | 7 | Same merchant and amount a few hours later |
| `night_purchase` | 6 | 02:00–04:59, unrelated to the event |
| `foreign_non_trip` | 5 | DE/GB/US/NL/FR merchant on a non-trip event |
| `amount_outlier` | 5 | 5–10× the event's normal merchant median |
| `after_event` | 4 | 5–9 days after the event ended |
| `hard_negative` (legit) | 8 | Unusual but legitimate: €420 of Arduino hardware for a workshop, a €950 hostel abroad on a trip, a €1,450 Law Ball dinner, a 01:35 taxi after a cast party |

### Split

The 2025/26 purchases are split **70% history / 30% evaluation**, *stratified by label* so every anomaly type appears in the eval set. Neither the rules nor JEV is trained on the data. History only provides context (society baselines, purchaser patterns, precedents). The JEV context for an eval purchase uses **as-of** data only (purchases before it), so there's no look-ahead.

## Assumptions (stated, not verified)

* Typical Irish student-event prices: e.g. pizza ≈ €2–4 per head, coach hire €400–500/day, hostel €25–40 per person per night. These are our estimates for plausibility, not CSO statistics.
* Alcohol (MCC 5813/5921) is **review**, not blocked. UCD/SU policy on society alcohol spend is unverified, so it's configurable by the Societies Office.
* Per-event cards match how societies budget (assumption A5 in the PRD).

## Baselines for claims

* **Evaluation:** "JEV adds value" is measured against the **rules-only** configuration on the same labelled eval set (precision, recall, F1, false flags per society per month, p95 latency, cost per 100 analyses). See the in-app Evaluation page or `npm run eval`.
* We make **no** time- or money-saving claims about real treasurers; those are hypotheses to test in a pilot (see PRD §3.4).
